# ADR 0005: גישת Let Agents לחנות דרך תוסף עם טוקן לקריאה בלבד

תאריך: 17 בספטמבר 2026
סטטוס: התקבל. מומש בתוסף 0.1.0.

## הקשר

Let Agents צריכה לקרוא מהחנות מוצרים, וריאנטים, קטגוריות, מאפיינים, שדות מותאמים ותוכן. ה־Store API הציבורי של WooCommerce לא חושף שדות מותאמים, מאפיינים מותאמים, מוצרים שאינם מפורסמים, ויחסי upsell ו־cross-sell. אביעד ביקש גישה מלאה לאתר דרך טוקן.

## החלטה

- **התוסף מייצר טוקן אחד**, `lat_` ועוד 48 תווים (טוקנים ישנים מתחילים ב־`rgt_` וממשיכים לעבוד), במסך WooCommerce > Let Agents. נשמר רק hash SHA-256. הטוקן מוצג פעם אחת. החלפה מבטלת את הקודם מיד.
- **גישת קריאה מלאה לקטלוג ולתוכן, ובלי כתיבה.** אין נתיב כתיבה, ואין נתיב ללקוחות, הזמנות או משתמשים. גישת כתיבה לא נדרשת לבניית הפיד, ובאתר חי היא סיכון מיותר.
- **REST תחת `let-agents/v1`**, עם הטוקן בכותרת `X-LetAgents-Token`. נתמך גם `Authorization: Bearer`, אבל יש שרתים שמסירים את הכותרת הזו.
- **נעילה אחרי 20 ניסיונות כושלים** מאותה כתובת IP לעשר דקות, לפי REMOTE_ADDR בלבד.
- **מאפיינים מיוצאים גולמיים.** הנרמול ליחידות, כמו "550W" ל־power_w = 550, קורה ב־Let Agents, כדי שאפשר יהיה לבדוק אותו.
- **עמוד לפי מזהה עולה**, עם `after` ו־`since`. מוצר נחשב שהשתנה גם כשרק וריאנט שלו השתנה.
- **hash לכל רשומה**, כדי ש־Let Agents תעבד רק את מה שהשתנה.
- **מחיר ומלאי בפיד משמשים לחישוב בלבד.** לגולש מוצגים ערכים חיים.

## בדיקות

- הבדיקות רצות על WordPress ו־WooCommerce אמיתיים ב־WordPress Playground, על PHP 8.1 ובאתר בעברית, גם מקומית וגם ב־CI.
- בדיקת lint על PHP 8.1, וידוא שכל מחרוזת מתורגמת לעברית, ובניית zip.

## השלכות

- חיבור החנות ב־Let Agents שומר כתובת אתר וטוקן מוצפן, ובודק אותו מול `/let-agents/v1/status`.
- בשלב הבא התוסף יקבל מפתח Let Agents בכיוון ההפוך, לשליחת webhooks ולהזרקת הרכיב.
