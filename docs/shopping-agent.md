# סוכן קנייה — תוכנית

> **עדכון:** 2026-10-15. **סטטוס:** הצעה, לפני פיתוח. **החלטה:** אחרי ניסוי העלות והאיכות (§7).
> **מה זה המסמך:** סוכן שבונה לקונה סל מלא ("סל כלי גינה עד 1000 ₪", "תבנה לי פרגולה 3×4") ומסיים בקישור אחד לתשלום עם הכול בסל: הכלים שלו, מה קוד ומה מודל, המתג והתקרה לכל חנות, העלות, ניסוי לפני החלטה, והשלבים.

## העיקרון

**קוד לפני מודל** (ADR 0002). המודל מבין מה הקונה רוצה ובוחר מבין מועמדים. כל מה שחייב להיות מדויק נעשה בקוד: מחיר, מלאי, אורך, כמות, סכום, וקישור הסל.

```
הקונה → הבנת הבקשה (מודל) → חיפוש וסינון (קוד) → מלאי ואפשרויות (קוד)
      → בחירה מבין 20–40 מועמדים (מודל) → בניית הסל ובדיקה (קוד) → תשובה + קישור
```

המודל **לא** אחראי על: מחירים, מלאי, חישוב סכום, כמויות זמינות, או בניית כתובת הסל.

## 1. שלב 0 — אורכים כמידע מסודר (גואטה)

בלי זה אף מודל לא יכול לחשב פרגולה, ולכן זה ראשון.

**מה ראינו:** בגואטה האורך הוא שדה תוסף (WooCommerce Product Add-Ons, תצוגה `gueta-length`), לא וריאציה. המחיר בקטלוג הוא למטר (למשל ₪13.28), והאפשרות מוסיפה אחוז: 5.40 מטר = +440% = ₪71.69. המידע לא נמצא ב‑Store API ולא במה שהתוסף שלנו שולח (`_product_addons` מדולג כשדה פנימי). הוא נמצא רק בעמוד המוצר. קישור הוספה לסל עם האורך (GET או POST) **לא** הוסיף לסל בבדיקה.

**מה בונים:**

1. **קריאה מעמוד המוצר בצד שלנו** (בלי התקנה אצל החנות): פעם ביום, רק למוצרים שיש להם שדה כזה (הסימון נשמר אחרי הקריאה הראשונה), בקצב מנומס. נשמר כאפשרויות מסודרות:
   `options: [{kind: "length", label: "5.40 מטר", meters: 5.4, price: 71.69, addon_key: "addon-14283-אורך-0", addon_value: "5-40-מטר-1"}]`
2. **בסל:** מוצר שדורש אורך מסומן "נדרשת בחירת אורך". אם הסוכן כבר בחר אורך, הוא מוצג מסומן מראש. דף ההזמנה שלנו מראה את כל הסל: הרגילים נכנסים בלינק אחד, ולכל מוצר עם אורך יש כפתור לעמוד שלו עם הסבר מה לבחור.
3. **בהמשך, עדכון לתוסף:** מייצא את ה‑add-ons כנתונים, ונקודה בחנות שמכניסה לסל כמה מוצרים עם האורך שנבחר ועוברת לתשלום. זה הפתרון המלא, אבל צריך התקנה אצל החנות. הוא ממלא רק את הסל של הקונה שלחץ ולא נוגע בנתוני החנות.

## 2. הכלים

אותם כלים משרתים את הסוכן שלנו **וגם** את אפליקציית Lets Search ב‑ChatGPT/Claude.

| כלי | מה עושה | מי |
|---|---|---|
| `search_products(query, filters)` | חיפוש במילים + מסננים: `category`, `min_price`/`max_price`, `in_stock`, מאפיינים (מתכת, צבע, מידה). מחזיר מועמדים קצרים | קוד |
| `get_product(id)` | פרטים, נקודות מפתח, מראה, אפשרויות ואורכים עם מחיר לכל אחד, מלאי | קוד |
| `find_alternatives(id, criteria)` | `cheaper` / `better` / `similar`: מאותו סוג, לפי מחיר ודירוג או לפי וקטור התמונה | קוד |
| `calculate_cart(items)` | בודק כל פריט: קיים, במלאי, כמות ≤ מלאי, אפשרות/אורך תקפים. מחזיר סכום, מה חסר ומה הוחלף | קוד |
| `create_cart(items)` | קישור אחד לתשלום. **חוסם כמות מעל המלאי בצד השרת**, לא רק בהנחיה | קוד |
| `plan` (מצב שמור) | הסל, התקציב והאילוצים נשמרים אצלנו לפי מזהה שיחה; שאלת המשך ("תחליף את המגרפה") שולחת רק את השינוי | קוד |

**פרויקט (פרגולה):** המודל מפרק לרשימת חלקים עם מידות והנחות (גובה, מרווח קורות), והכלים מוצאים לכל חלק מוצר ואורך. הכמויות מחושבות בקוד מהמידות. ההנחות נכתבות לקונה במפורש.

## 4. מתג ותקרה לכל חנות

**מתג:** דגל `agent.enabled` ב‑`module.json`, **כבוי** כברירת מחדל. לכל חנות: ירושה / מופעל / כבוי. כבוי = הכפתור לא נבנה, הנתיב מחזיר 404, והכלים באפליקציה לא מציעים את החנות.

**תקרות** (הגדרות typed ומוגבלות, לכל חנות עם ברירת מחדל גלובלית):

| הגדרה | ברירת מחדל | גבולות | מה קורה כשמגיעים |
|---|---|---|---|
| תקרה חודשית לסוכן (בתוך `ai.shop_monthly_cap_usd`) | 10 $ | 0–500 | הסוכן נכבה עד החודש הבא, והקונה מקבל את הדרך החינמית: "לשאול את ה‑AI שלי" (קובץ ה‑JSON) |
| שיחות לחנות ביום | 200 | 0–5000 | כמו למעלה, עד מחר |
| עלות לשיחה אחת | 0.05 $ | 0.01–1 | השיחה מסתיימת בסל שכבר נבנה, עם הקישור |
| תורות לשיחה | 8 | 2–30 | כמו למעלה |
| שיחות לגולש ביום | 5 | 1–50 | הודעה ידידותית, ומחר שוב |
| שיחות לכתובת IP ביום | 20 | 1–200 | כמו למעלה; הפרות חוזרות → חסימה (הדפוס של `Assistant`) |

**מסכים:**
- **הסוחר** (מסך הסוכן): מתג, תקרה חודשית בשקלים שהוא בוחר מתוך טווח שהמפעיל מתיר, אחוז ניצול (לא סכום ולא שם מודל), כמה סלים נבנו וכמה מהם נפתחו.
- **המפעיל:** דולרים, טוקנים, מודלים, עלות ממוצעת לשיחה, וחריגים.

**אף פעם שגיאה לקונה:** כל תקרה מובילה לדרך שעובדת: סל שכבר נבנה, החיפוש הרגיל, או הקישור ל‑AI של הקונה.

## 5. עלות משוערת

לפי מחירי ההגדרות (`gpt-5.4-mini` 1$/8$ למיליון). **לא אומת מול המחירון של OpenAI**; הניסוי (§7) מודד את האמת.

| מקרה | קלט | פלט | עלות |
|---|---|---|---|
| "סל גינה עד 1000" | ~3K טוקנים (40 מועמדים) | ~0.6K | ~0.008 $ |
| "תבנה לי פרגולה" (פירוק + 5 חיפושים + בדיקה) | ~8K | ~1.5K | ~0.02–0.03 $ |
| שאלת המשך עם מצב שמור | ~1K | ~0.3K | ~0.003 $ |
| בקשה זהה (טביעת אצבע) | 0 | 0 | 0 $ |

לדוגמה, 1,000 שיחות בחודש לחנות ≈ 10–25 $.

- **הכללים נשמרים:**
  - אין קריאת מודל בטעינת עמוד או בהקלדה;
  - רק לחיצה/שליחה של הקונה מתחילה שיחה.

## 7. ניסוי לפני החלטה

**מטרה:** לדעת עלות ואיכות אמיתיות לפני שפותחים לקונים.

- **25 שאלות אמיתיות מגואטה:**
  - 8 סלים לפי תקציב;
  - 6 פרויקטים (פרגולה, שולחן קק"ל, גדר, מדף);
  - 5 החלפות ("תחליף את X בזול/טוב יותר");
  - 4 שאלות המשך בשיחה;
  - 2 בקשות למוצר שאין בחנות.
- **שני מסלולים לכל שאלה:**
  - **(A)** ChatGPT עם קישור ה‑JSON. חינם לנו; אתה מריץ ידנית.
  - **(B)** הסוכן שלנו, מתוך `artisan agent:trial`. עובד רק אצלנו, בלי קונים.
- **הדוח, לכל שאלה:**
  - עלות (מ‑`ai_ledger`) וזמן;
  - המוצרים שנבחרו;
  - האם הקישור פותח סל נכון;
  - האם הסכום והכמויות נכונים;
  - הערכה ידנית שלך (1–5) לאיכות הבחירה וההסבר.
- **עלות הניסוי:** כ‑1 $.
- **תנאי מעבר:**
  - 0 קישורים שבורים;
  - 0 טעויות סכום;
  - ≥ 4/5 ממוצע בהערכה;
  - ≤ 0.03 $ לשאלה;
  - ≤ 6 שניות לתשובה.

## 9. שאלות פתוחות

1. **ברירת המחדל לתקרה החודשית:** 10 $ לחנות? והאם הסוחר רשאי להעלות אותה, ועד כמה?
2. **מה הקונה רואה כשהתקרה נגמרה:** הקישור ל‑AI שלו (מוצע), או רק החיפוש הרגיל?
3. **קריאת עמודי מוצר בגואטה פעם ביום:** בסדר מבחינתם? בערך כמה עשרות עמודים, בקצב איטי.
4. **מי מעריך את תוצאות הניסוי:** אתה, או גם מישהו מגואטה?
